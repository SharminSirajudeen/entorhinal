A memory for your AI that notices when something new makes an old fact untrue, and checks your question against it before answering.

Your sessions and questions are sent to NVIDIA Nemotron models on Nebius Token Factory to be read and answered. Your memory is kept on this server apart from every other visitor's, found by one cookie, and deleted 24 hours after your first visit; Export and Delete everything are below.

      How it works

      If a memory only adds facts and retrieves them, a fact that a newer session has made untrue is still retrieved, and the model answers from it: directly changed (you moved city) or changed by consequence (a leg in a cast ends the daily bike ride). STALE measures exactly this failure. Entorhinal makes no longer true a state in the memory, decided by a model when the change arrives, and checks every question's assumptions against it before answering.

      Data model

      Fact(id, subject, attribute, value, time, source_idx, status, invalidated_by, reason), with status held to active or stale by a CHECK constraint, in one SQLite file per user. A fact that goes stale is kept, never deleted: it carries the id of the fact that replaced it and the judge's one-sentence reason, so every correction can be traced to the session that caused it.

      Write path, once per session

      1. Extract. Nemotron 3.5 Lightning, JSON mode, up to 1,500 output tokens: every fact the user reveals, dated with the session time.
      2. Relate. Every active fact on a subject the new facts touch or name, oldest first, with no cap: in a pilot, a cap of the 40 newest hid the very fact a session changed.
      3. Judge. Nemotron 3 Super, reasoning on, up to 12,000 output tokens: only the old facts the session makes untrue, implied consequences included, each with a verdict, the new fact that caused it and a reason.
      4. Store. Each such fact is rewritten in place as stale, linked to its cause (INSERT OR REPLACE by id).

      Read path, once per question

      1. Check. Nemotron 3 Super, reasoning on, up to 8,000 output tokens: each assumption the question makes about the user's situation now, marked SAFE, OUTDATED or UNRESOLVED. "Not mentioned" is never OUTDATED, and OUTDATED names the stale fact it rests on.
      2. Answer. Nemotron 3 Super, reasoning off, up to 2,000 output tokens: an outdated assumption is corrected first, citing the newer fact and its date, then the question is answered for the user's situation now.

      Failure, replay and cost

      A reply that does not parse yields no facts and no decisions, never an exception. A reply cut off at its token cap is refused, never half-applied, yet billed and counted against the day's spend cap. Every benchmark call is recorded under the SHA-256 of its request body; with REPLAY=1 a missing recording is an error, so the test suite and the three recorded memories above re-run for $0. At list prices per million tokens (Lightning $0.06 in, $0.24 out; Super $0.30 in, $0.90 out), building one 50-session memory cost about $0.37 in our run, and one question cost $0.009 to $0.012 there (a live one on 29 Oct, on the design-subscription memory: $0.016).

      Measured

      12 STALE scenarios (seed 11, six of each type) that none of our fixes were made on, all three probing questions each; judge: Nemotron 3 Ultra with STALE's own prompt, temperature 0. Type 1 is a direct change, Type 2 an implied consequence. SR: knows the old fact may be outdated. PR: refuses a stale premise. IPA: plans for the new situation.

      Limits

      • 12 scenarios is a small sample: on 9 others, grading the same answers twice moved PR from 6/9 to 7/9.
      • Type 2, the implied consequence, is the weak side: 6/18 against Type 1's 12/18.
      • On long memories the change judge also marks some unrelated facts untrue; "Only the facts made untrue" shows them.
      • In the run, 52 change-judge calls stopped at their token cap and were refused, so their sessions may hold changes the memory never recorded.
      • The change judge reads every active fact on the subject each session, so its input grows with the memory.

      Hosting: one SQLite file per browser, found by an HttpOnly cookie and deleted after 24 hours; the page makes no request to any other origin (CSP default-src 'self'); a daily spend cap refuses new work once reached. The code, the reports and every recorded reply are in the entorhinal repository on GitHub.
