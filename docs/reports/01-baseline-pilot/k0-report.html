STALE Pilot K0

Can a personal AI built on Nemotron notice when something new in a person's life quietly makes an old memory untrue, and refuse to act on the stale one? This is the first measured run, on the public STALE benchmark.

Run: 28 Oct 2026, on Nebius Token FactoryBenchmark: STALE (arXiv 2605.06527)20 scenarios, seed 7
Passed

Kill test passed. The rule written before the run said: continue only if our approach beats plain Nemotron on Premise Resistance. It did, 0 of 20 → 8 of 20.

Premise Resistance means the AI refuses a question built on a fact that is no longer true. On the paper's table, memory products score 0–2% on it.

What ran

1 · Nemotron 3.5 Lightning · thinking offRead each sessionEach of ~50 sessions is read separately, and the facts the user reveals are listed with the session's date. About 50 small calls per scenario.
2 · Nemotron 3 Ultra · thinking onFind what changedUltra reads the dated fact list and names every older fact that a later one makes untrue, including implicit consequences.
3 · Nemotron 3 Super 120B · thinking offAnswer, checking assumptionsList the question's assumptions, check each against the newest facts, correct any stale one with its date, then answer.
  • Baseline: Nemotron 3.5 Lightning gets the whole history (150,149–168,827 tokens; average 158,649) and answers. STALE's own prompts and history format, unchanged.
  • Grader: Nemotron 3 Ultra with STALE's own judge prompt, unchanged, temperature 0, JSON output. One call per scenario per condition grades all three answers.
  • Sample: 20 of the 400 scenarios, drawn with a fixed seed (7): 10 Type I, 10 Type II. All three question types per scenario (60 graded answers per condition).
  • Setting that mattered: chat_template_kwargs.enable_thinking = false on every call except step 2. Without it, Nemotron writes its thinking into the answer text and runs out of space.

What this does and doesn't show

  • Shows: on Nemotron, a memory that records dated facts and uses Ultra's reasoning to find what changed beats reading the raw history. 0 → 8 of 20 on stale premises, 10.0% → 48.3% overall.
  • Doesn't show: a number comparable to the paper's table. The grader differs (Ultra vs Gemini-3.1-flash-lite) and the sample is 20 of 400, run once.
  • Noise: identical code gave different grades on back-to-back pilot runs. The measured run (task T9) uses 100 scenarios.
  • Still behind the authors' system: CUPMem reports 78% / 75% on stale premises. Ours is a crude first pipeline, and the build adds write-time invalidation (each new fact checked against related old ones).
  • Where it misses: 4 scenarios failed every question, mostly changes that only hold implicitly (time zone, screen-time habit, residency).
